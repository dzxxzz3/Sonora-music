# SONORA Music Studio — локальный MVP

SONORA — адаптивный музыкальный веб-интерфейс с локальной библиотекой. Эта версия включает импорт аудиофайлов в IndexedDB, реальное воспроизведение файлов через браузер, избранное, плейлисты, экспорт метаданных в JSON и M3U, поиск по локальной коллекции, офлайн-страницу и PWA shell cache.

> Важно: это честный MVP, а не завершённый коммерческий сервис. Spotify и SoundCloud OAuth/API не подключены: интерфейс показывает, что настройка требуется, а backend намеренно не имитирует успешную авторизацию. Для полноценной интеграции необходимо реализовать и проверить текущие официальные OAuth-потоки и разрешённые API-сценарии.

## Требования

- Node.js 20 или новее
- npm
- Современный браузер с IndexedDB и HTMLAudioElement

## Запуск на Arch Linux

Проверьте установку Node.js/npm:

```bash
sudo pacman -S nodejs npm
node --version
npm --version
```

В корне проекта:

```bash
npm install
cp .env.example .env
npm run dev
```

Откройте `http://localhost:5173`.

В другом терминале можно запустить API-заглушку статуса интеграций:

```bash
npm run server
```

Проверка: `http://localhost:8787/api/health`.

Для тестов:

```bash
npm test
```

Production-сборка frontend:

```bash
npm run build
npm run preview
```

## Использование

1. Нажмите «Добавить музыку» и выберите аудиофайлы.
2. Файлы и метаданные сохраняются в IndexedDB этого браузера/профиля.
3. Запустите трек нажатием на обложку/название.
4. Создайте плейлист в боковой панели или разделе «Плейлисты».
5. В разделе «Моя музыка» нажмите `+` у трека, чтобы добавить его в плейлист.
6. Экспортируйте метаданные в JSON или структуру плейлиста в M3U.
7. После production-сборки Service Worker кэширует оболочку приложения. Аудиофайлы остаются в IndexedDB и доступны без сети, если браузер не очистил данные и сайт ранее был открыт.

## Ограничения офлайн-режима

- Offline доступен для файлов, которые пользователь сам выбрал и которые браузер разрешил сохранить.
- Экспорт JSON сохраняет только метаданные; сами аудиофайлы в него не включаются.
- M3U экспортирует имена файлов, а не абсолютные пути. Внешний плеер может потребовать исправить пути.
- Браузер может ограничивать квоту и очищать хранилище. Держите резервные копии исходных файлов.
- Фоновое воспроизведение зависит от ОС, браузера и политики энергосбережения.

## Spotify / SoundCloud

1. Создайте приложение в официальном кабинете соответствующего поставщика, если регистрация приложений доступна для вашего аккаунта/региона.
2. Укажите точный redirect URI, совпадающий с настройками поставщика.
3. Заполните переменные в `.env` на сервере. Никогда не добавляйте client secret в переменные `VITE_*` или клиентский код.
4. Реализуйте authorization-code flow с `state`/PKCE согласно текущим официальным требованиям, серверной сессией, проверкой callback, безопасным хранением/обновлением токенов и logout.
5. Используйте только разрешённые scopes/endpoints и соблюдайте лимиты API и условия платформы. Возможность регистрации, доступные поля и scopes могут меняться.
6. Добавьте контрактные тесты и проверку на тестовом аккаунте до включения функции в интерфейсе.

Backend сейчас предоставляет `/api/health`, `/api/integrations`, валидацию экспорта и честно возвращает `501` для не реализованного OAuth. Он не хранит токены и не выполняет запросы к музыкальным платформам.

## Известные ограничения текущей версии

- Извлечение ID3/FLAC-тегов и длительности из файлов пока не подключено; название берётся из имени файла, длительность появляется после загрузки трека в плеер.
- Поиск работает по локальной библиотеке; внешние каталоги пока не подключены.
- OAuth Spotify/SoundCloud, межсервисное сопоставление, серверная БД/аккаунты и полноценные фоновые медиа-сессии ещё не реализованы.
- Нет фиктивных треков: пустые состояния остаются пустыми, пока пользователь не добавит музыку.
